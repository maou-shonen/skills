## 觀察到的原則

- **呈現優先，技術其次。** 核心是用簡單的幾何圖形把 UI「畫出來」（純 CSS 或 SVG）：圓角磚、膠囊、圓點、線條、框、對話泡、■＋●✕ 符號列。用 CSS 還是 motion 做只是手段。
- **畫出來，不是淡入。** 重要的東西是被描線、被色塊擦出、被堆疊出來的；淡入只給次要元素。
- **低彩度舞台加一個強調色。** 白或近白底、灰色面板、灰色小字；強調色出現在「正在被畫」的地方（筆尖、擦除、CTA）。
- **安靜的裝飾。** 低對比的幾何小圖形放在邊角，不搶內容。
- **小故事。** 一個關鍵動作是有因有果的小場景（推、拉、倒下再站穩）。用設計者的方式思考，給自己限制（只用位移、只用線）。
- **字體。** 粗標題配小 kicker；標題和角色台詞可以用圓體或手寫體。
- **角色。** yui540 用大量 Q 版貓。我們不模仿他的貓：角色要依專案主題個別設計，用基本形狀組成。

## 兩種風格偏好（保留，未定案）

| | refined（工作、公開 UI） | expressive（個人用） |
|---|---|---|
| 裝飾 | 少量低對比幾何裝飾 | 較多，可有小迴圈 |
| 字體 | 標題和角色台詞可用圓體或手寫 | 同左，新站可用圓體當 UI 字體 |
| 角色 | 只在空狀態、404、長時間載入、成功時出現；是否說話未定 | 常駐，可說話可點 |
| 強調色 | 少量 | 較多（曾暫定 ≤12%，未驗證） |

## rakuyomu 試驗的教訓

- **面積下限會逼出無意義的裝飾。** v7 規定裝飾和強調色至少佔畫面 0.5%，結果出現跟內容無關、還一閃一閃像載入中的方格，和一條沒有作用的橘色底線。裝飾應該從內容或主題長出來，沒有合適的就不放。
- **角色破壞版面。** 角色被當成版面的一格塞在標題旁，把標題推離左邊線，手機上對話泡被切掉。角色要疊在版面上、不推移格線；角色也不是主角，書架才是。
- **組裝感，不是畫出來。** 每一版開場都像元件拼起來（遮罩揭示為主），不像被畫出來。可能的方向：先描線框再填色。
- **規則越多越保守或越亂。** 只給技巧時畫面平淡（#329）；全部放大又沒主角（#328）；加上主角／高潮／面積規則後，產出變成在滿足規則。
- **驗收要親眼看截圖。** 斷言通過但截圖有問題的情況出現過多次（對話泡壓到裝飾、兩張截圖相同、文字只量外框被切掉）。
